# Руководство по участию в разработке (Contributing Guide)

Спасибо за интерес к развитию проекта **WEEEK → Linear Migration Tool**!

## Правила и стандарты разработки

1. **Язык общения и документации**: В соответствии с правилами проекта все обсуждения, комментарии к коду и документация ведутся на **русском языке** (в коде идентификаторы — на английском).
2. **Ведение CHANGELOG**: Каждое значимое изменение должно сопровождаться записью в `docs/CHANGELOG.md`.
3. **Архитектурная документация**: Если вносятся изменения в API или движок, обязательно обновите соответствующие файлы в `docs/` (`API_ARCHITECTURE.md`, `MIGRATION_ARCHITECTURE.md` и др.).
4. **Тестирование**: Все новые функции, мапперы и обработчики ошибок должны быть покрыты тестами в директории `tests/` с помощью `vitest`.
5. **Безопасность**: Запрещено коммитить токены, пароли, фикстуры с персональными данными. Используйте анонимизированные моки.

---

## Процесс локальной разработки

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/denis-ershov/weeek-to-linear.git
   cd weeek-to-linear
   ```

2. Установите зависимости:
   ```bash
   pnpm install
   ```

3. Создайте локальный файл `.env`:
   ```bash
   cp .env.example .env
   ```

4. Запуск проверок качества:
   ```bash
   pnpm typecheck   # Проверка TypeScript
   pnpm lint        # ESLint
   pnpm test        # Vitest
   pnpm build       # Сборка CLI
   ```

5. Локальный запуск CLI в dev-режиме:
   ```bash
   pnpm dev auth:test
   ```

## Оформление Pull Request

- Создавайте ветку от `main` с понятным именем: `feat/issue-batch-support`, `fix/status-mapping-bug`.
- Убедитесь, что все тесты и линтер проходят локально (`pnpm test && pnpm typecheck && pnpm lint`).
- Опишите изменения в шаблоне PR.
