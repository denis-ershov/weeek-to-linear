# Архитектура Web UI (UI_ARCHITECTURE.md)

## 1. Введение и назначение

Web UI предоставляет визуальное, интерактивное и безопасное управление миграцией данных из WEEEK в Linear.
Интерфейс спроектирован по принципу **Mobile First** и стандартам современного веб-дизайна (**Linear / Vercel / Raycast**).

---

## 2. Структура компонентов

```
src/server/
├── server.ts             # WebServer: локальный HTTP сервер (node:http)
├── routes.ts             # ApiRouter & SseManager: REST API + SSE стриминг
├── types.ts              # DTO запросов, ответов и событий
├── public/
    ├── favicon.svg       # Векторный фавикон высокой четкости (Quantum Bridge)
    ├── logo.svg          # Горизонтальный векторный логотип с типографикой
    ├── index.html        # Семантический каркас Mobile First
    ├── app.css           # Дизайн-система (Linear Dark, Glassmorphism, Анимации)
    ├── app.js            # Реактивное SPA управление состоянием
    └── i18n.js           # Клиентская система локализации RU/EN
```

## 3. Дизайн-система и UI/UX токены

### Фирменный знак, Логотип и Favicon («Quantum Bridge — Neon Portal»)

Фирменный знак проекта символизирует непрерывный высокоскоростной перенос данных из WEEEK в Linear:

- **Форма знака**:
  - Скругленный суперэллипс (squircle) с темным ночным градиентом Linear (`#151722` $\rightarrow$ `#0A0B10`), деликатной градиентной окантовкой и мягким неоновым свечением.
  - Непрерывная траектория **W $\rightarrow$ Linear Arrow**: левый сегмент литеры «W» плавно трансформируется через динамический цветовой мост в направленный вектор со стрелкой Linear.
- **Цветовая палитра («Neon Portal»)**:
  - **WEEEK Core**: теплый энергичный оранжевый (`#FF7A30` $\rightarrow$ `#FF6B2B`).
  - **Световой портал перехода**: яркая маджента (`#FF3864`) и электрический аметист (`#7C3AED`), исключающие появление блеклых и грязных оттенков в RGB-спектре.
  - **Linear Indigo & Velocity**: ультрамариновый индиго (`#6366F1` / `#5E6AD2`) с акцентным наконечником цвета лазурного луча (`#818CF8`).
- **Форматы и масштабируемость**:
  - `favicon.svg` подключен в `<head>` через `<link rel="icon" type="image/svg+xml" href="favicon.svg">`, оптимизирован для размеров $16 \times 16$, $24 \times 24$, $32 \times 32$ и $48 \times 48$ px.
  - `logo.svg` предоставляет полноразмерный горизонтальный lockup для шапки, документации и маркетинговых материалов.

### Адаптивность и Mobile First

- **Mobile First дизайн**: адаптивная сетка и стили оптимизированы для всех категорий экранов — от iPhone SE (375px) до 4K Ultra HD мониторов.
- **Преобразование таблиц в карточки (Правило 10-11)**: на экранах шириной $\le 640$ px традиционная таблица сопоставления колонок и статусов (`.mapping-table`) автоматически трансформируется в стек независимых карточек (`display: block`) с читаемыми лейблами через псевдоэлементы `td::before`, устраняя горизонтальный скролл.
- **Доступность и Tap Targets (Правило 16)**: для всех кнопок, переключателей радио-групп, полей ввода и селектов обеспечен минимальный размер области взаимодействия $\ge 44 \times 44$ px (`min-height: 44px`, `touch-action: manipulation`).
- **Защита от утечек памяти (Memory Leak Prevention)**: при длительных миграциях на тысячи сущностей контейнер живых логов консоли (`liveConsoleLogs`) использует ограниченный кольцевой буфер (`MAX_LOG_ENTRIES = 500`). При превышении лимита старые узлы DOM автоматически удаляются через `logContainer.firstChild.remove()`, предотвращая деградацию производительности и рост кучи браузера.
- **Двуязычная локализация**: поддержка мгновенного переключения языков (Русский / Английский) с персистентным хранением выбора в `localStorage` и 100% паритетом ключей словарей.

### Компоненты гибкой маршрутизации (Routing Engine Controls)

1. **User & Role Routing Card**:
   - Выпадающий список выбора стратегии дефолтного исполнителя (`selectFallbackAssignee`: `unassigned`, `creator`, `specific_user`). При выборе `specific_user` плавно раскрывается селектор сотрудников Linear.
   - Выбор стратегии атрибуции автора задачи (`selectCreatorStrategy`: `header`, `subscriber`, `both`, `none`).
   - Индивидуальный список сопоставления пользователей WEEEK $\rightarrow$ Linear:
     - Полный состав команды воркспейса WEEEK (загрузка через `/ws/members` с объединением `firstName` и `lastName`).
     - Автоматическое выявление скрытых авторов задач и комментариев (`role: 'task_author'`) при передаче выбранных `projectIds`.
     - Отображение аватарок пользователей, реальных имен и бейджей ролей (`Владелец`, `Администратор`, `Автор задач/комментов`).
     - Единое сопоставление применяется как для исполнителей задач, так и для авторов комментариев и наблюдателей.
2. **Comment Routing Controls**:
   - Выбор стратегии для не сопоставленных авторов комментариев (`selectFallbackCommentAuthor`):
     - Указывать реальное имя автора в шапке комментария (`use_name`, по умолчанию).
     - Привязывать все не сопоставленные комментарии к выбранному сотруднику Linear (`specific_user` с динамическим селектором `selectFallbackCommentUser`).
     - Отправлять комментарии от имени сервисного бота без привязки (`bot_label`).
   - Переключатель автоматической подписки авторов комментариев (`optSubscribeCommentAuthors`).
   - Переключатель фильтрации системных сервисных сообщений WEEEK (`optExcludeSystemComments`).
3. **Task Routing Rules Builder**:
   - Динамический список правил с кнопкой «+ Добавить правило».
   - Каждое правило содержит конструктор условий (поле: `tag`, `column`, `priority`; оператор: `contains`, `equals`; значение) и действий (назначить исполнителя / добавить наблюдателя из списка сотрудников Linear).
   - Адаптивный мобильный вид со стеком полей и сенсорной областью кнопки удаления $\ge 44 \times 44$ px.

### Состояния интерфейса

Каждый экран поддерживает 4 обязательных состояния:

1. **Loading**: скелетоны загрузки (`skeleton-card`) и спиннеры.
2. **Empty**: информативные пустые состояния с пояснениями.
3. **Error**: контрастные баннеры ошибок с возможностью повтора.
4. **Success**: карточки итогов и скачивание отчетов.

## 4. Спецификация REST API и SSE

| Метод  | Путь                  | Назначение                                                            |
| :----- | :-------------------- | :-------------------------------------------------------------------- |
| `GET`  | `/api/status`         | Проверка статуса сервера и предзагрузка токенов из `.env`             |
| `POST` | `/api/auth/test`      | Тестирование токенов WEEEK и Linear                                   |
| `GET`  | `/api/weeek/projects` | Список проектов WEEEK со счетчиками задач                             |
| `GET`  | `/api/weeek/users`    | Список участников WEEEK (`/ws/members` + сканирование по `projectIds`)|
| `GET`  | `/api/linear/teams`   | Список доступных команд Linear                                        |
| `GET`  | `/api/linear/states`  | Список Workflow состояний для выбранной команды                       |
| `GET`  | `/api/linear/users`   | Список пользователей Linear                                           |
| `POST` | `/api/migrate/start`  | Запуск конвейера миграции                                             |
| `POST` | `/api/migrate/stop`   | Остановка текущего процесса миграции                                  |
| `GET`  | `/api/migrate/stream` | Поток событий Server-Sent Events (SSE)                                |
| `GET`  | `/api/reports/latest` | Получение последнего сформированного отчета                           |
