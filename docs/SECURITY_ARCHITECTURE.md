# Архитектура безопасности (SECURITY_ARCHITECTURE.md)

## 1. Модель угроз (Threat Model)

Проект **WEEEK → Linear Migration Tool** публикуется как открытый исходный код, что требует строгого соблюдения принципов _Security by Design_ и _Zero Trust_.

### Анализ векторов атак и меры защиты (STRIDE)

| Угроза                                        | Вектор / Риск                                                             | Защитные меры в архитектуре                                                                                                                                                                 |
| :-------------------------------------------- | :------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Information Disclosure (Утечка секретов)**  | Случайный коммит `.env` или логов с токенами в публичный Git-репозиторий. | 1. Исключение `.env*`, `.weeek-linear/`, логов в `.gitignore`.<br>2. Автоматическое маскирование заголовков и токенов в `pino` (`redact`).<br>3. Сканирование Gitleaks в GitHub Actions CI. |
| **Credential Storage (Хранение токенов)**     | Утечка токенов через файл сохранения состояния.                           | Токены API **никогда** не сохраняются в `state.json` или отчетах.                                                                                                                           |
| **Data Tampering (Подмена данных)**           | Некорректная модификация задач в целевом Linear.                          | Валидация входных данных через `zod` и обязательный предстартовый `PreflightValidator`.                                                                                                     |
| **Denial of Service (DoS / Rate Limits)**     | Блокировка аккаунта из-за превышения квот API WEEEK/Linear.               | Ограничение параллелизма (`API_CONCURRENCY`), экспоненциальный retry и обработка `Retry-After`.                                                                                             |
| **Input Injection (HTML/Markdown Injection)** | Внедрение вредоносных тегов через описание задач WEEEK.                   | Санитизация Markdown и очистка потенциально опасного HTML перед отправкой в Linear.                                                                                                         |

## 2. Безопасность логов

Логирование построено на базе библиотеки `pino` с конфигурацией автоматического скрытия:

```typescript
const redactPaths = [
  'WEEEK_API_TOKEN',
  'LINEAR_API_TOKEN',
  'req.headers.authorization',
  'headers.authorization',
  '*.token',
  '*.apiKey',
  '*.password',
];
```

Даже в режиме `--log-level debug` заголовки авторизации и токены заменяются на `[REDACTED]`.

## 3. Обработка персональных данных (GDPR / Privacy)

1. Утилита выполняется исключительно на рабочей станции пользователя.
2. Промежуточные данные (маппинги ID и email) сохраняются в локальной директории `.weeek-linear/` и не отправляются на сторонние серверы.
3. Отчеты миграции (`migration-report.md`, `migration-report.json`) генерируются локально и по умолчанию исключены из Git.

## 4. Безопасность Web UI и HTTP-сервера

Встроенный сервер управления Web UI (`src/server/server.ts`, `src/server/routes.ts`) работает локально и защищен по стандарту глубокой эшелонированной обороны:

### 4.1. Защита от Path Traversal

- Статическая раздача файлов (`serveStatic`) проверяет сырой URL запроса (`req.url`) на наличие закодированных последовательностей обхода директорий (`%2e%2e`, `..`, `%2f`, `%5c`).
- Запросы за пределы базовой директории `public/` немедленно блокируются со статусом `403 Forbidden`.
- Пути нормализуются через `path.normalize`, а результирующий путь валидируется через `resolvedPath.startsWith(PUBLIC_DIR)`.

### 4.2. Ограничение CORS (Cross-Origin Resource Sharing)

- Запрещены подстановочные заголовки (`Access-Control-Allow-Origin: *`).
- Разрешены запросы исключительно с доверенных локальных источников (`http://localhost:*`, `http://127.0.0.1:*`) либо совпадающие с локальным хостом сервера.
- Внешние веб-сайты не могут выполнять запросы к локальному API миграции через браузер пользователя.

### 4.3. Защитные HTTP-заголовки

Каждый статический и API-ответ включает защитные заголовки:

- `X-Content-Type-Options: nosniff` — предотвращение MIME-sniffing атак.
- `X-Frame-Options: DENY` — защита от Clickjacking.
- `Referrer-Policy: no-referrer` — исключение утечки параметров в Referer.

## 5. Контроль цепочки поставок и управление уязвимостями (Supply Chain)

- Автоматический аудит зависимостей через `pnpm audit --audit-level=high` в CI пайплайне.
- Фиксация безопасных версий транзитивных зависимостей через секцию `pnpm.overrides` (например, `esbuild: >=0.28.1` для устранения CVE/GHSA-g7r4-m6w7-qqqr).
- Защита от утечки секретов с помощью сканирования `gitleaks` при каждом коммите и PR.
